Virtualizacion y Entorno:

Hipervisores, VirtualBox y WSL2

Que es la virtualizacion?

  • Tecnica que permite ejecutar uno o mas sistemas operativos invitados sobre una misma maquina fisica (anfitriona).
  • El componente clave es el hipervisor: reparte y aisla CPU, memoria, disco y red entre cada maquina virtual (VM).
  • Ventaja para estudiantes: podemos romper un servidor Linux o probar configuraciones riesgosas sin tocar nuestra PC real.
  • Ventaja en produccion: un servidor fisico puede correr decenas de servidores virtuales, maximizando la utilizacion del hardware.

La virtualizacion es la tecnologia base de toda la nube moderna (AWS, Azure, GCP).

Tipos de hipervisor

Caracteristica Tipo 1 (bare-metal) Tipo 2 (hosted)
Donde corre? Directo sobre el hardware Como aplicacion sobre un SO
Rendimiento Muy alto (Produccion) Suficiente para estudio/desarrollo
Ejemplos VMware ESXi, Proxmox, KVM VirtualBox, VMware Workstation
  • En produccion se usan hipervisores tipo 1.
  • Para aprender en nuestra PC, VirtualBox (tipo 2) es ideal por su sencillez.

Arquitectura de una Maquina Virtual

Que hay dentro de una VM?

Arquitectura interna de una VM

Una maquina virtual emula los mismos componentes que una PC fisica:

Componente virtual Equivalente fisico En VirtualBox
vCPU Nucleos del procesador Configurable (1-N cores)
RAM virtual Memoria RAM Porcion de la RAM del host
Disco virtual Disco duro / SSD Archivo .vdi / .vmdk
NIC virtual Placa de red Adaptador de red emulado
BIOS/UEFI virtual Firmware de arranque UEFI o BIOS emulado

El hipervisor intercede entre el hardware real y cada VM, traduciendo las instrucciones.

Modos de red en una VM

El modo de red define como la VM se conecta al mundo exterior:

Modo Internet? Visible desde host? Uso tipico
NAT Si No Acceso a Internet simple
Puente Si Si (IP propia en la red) Simular servidor en la LAN
Red interna No No (solo entre VMs) Labs de red aislados
Host-only No Solo host a VM SSH desde host, desarrollo local

Laboratorio: NAT para Internet + Host-only para SSH desde la PC.

Tipos de disco virtual

El disco de una VM es un archivo en el host. Existen distintos formatos y modos:

Concepto Descripcion
.vdi Formato nativo de VirtualBox. Recomendado para uso con VirtualBox.
.vmdk Formato de VMware, compatible con VirtualBox. Portable entre plataformas.
Reservado dinamico El archivo crece a medida que la VM escribe datos. Ahorra espacio en el host.
Tamano fijo El archivo ocupa el maximo desde el inicio. Mejor rendimiento de I/O.

Laboratorio: .vdi con reservado dinamico, 20-30 GB.

Snapshots:

El superpoder de las maquinas virtuales

Snapshots: guardar el estado de una VM

  • Un snapshot (instantanea) guarda el estado completo de la VM: disco, RAM y configuracion en un momento dado.
  • Permite volver atras si algo sale mal.
  • Caso de uso tipico: antes de actualizar el sistema o instalar un servicio, sacamos un snapshot. Si falla, revertimos en segundos.
  • Se pueden encadenar multiples snapshots formando un arbol de estados.

En el laboratorio, siempre sacar un snapshot antes de cada practica riesgosa. Es lo que hacen los admins en produccion.

Flujo tipico con snapshots


VM instalada y configurada
        |
        v
  [Snapshot 1: Base limpia]
        |
        v
Instalo Nginx, configuro firewall...
        |
   Funciona? --- Si --> [Snapshot 2: Con Nginx]
        |                    |
       No                    v
        |              Sigo trabajando...
        v
Revierto a Snapshot 1
y empiezo de nuevo
  • Los snapshots no reemplazan los backups: son para pruebas rapidas.
  • Muchos snapshots acumulados degradan el rendimiento del disco virtual.

Herramientas del Laboratorio:

VirtualBox y WSL2

VirtualBox: nuestro entorno

  • Hipervisor de tipo 2, gratuito y de codigo abierto (Oracle).
  • Permite crear una VM con disco virtual, RAM y placas de red virtuales para instalar un servidor Debian/Ubuntu completo.
  • Todo lo que hagamos dentro de la VM queda aislado del sistema anfitrion.
  • Consola de administracion grafica y CLI (VBoxManage).
  • Compatible con Windows, macOS y Linux como sistema anfitrion.

Descarga: virtualbox.org

WSL2: una alternativa distinta

  • WSL2 (Windows Subsystem for Linux 2) corre un kernel Linux real dentro de Windows sobre una VM ligera (Hyper-V).
  • Integracion nativa con Windows: acceso directo a archivos y buen rendimiento de red.
  • Ideal para tener una terminal Linux rapida en Windows.
  • Limitacion: no simula hardware completo - sin BIOS, UEFI ni particionado como un servidor real.

VirtualBox vs WSL2

Criterio VirtualBox (VM completa) WSL2
Que instala SO completo (Debian/Ubuntu Server) Distro Linux integrada a Windows
Ideal para Simular servidor real, red, particionado Uso diario de CLI desde Windows
Aislamiento Total (disco, red, hardware) Parcial (mas integrado)
Uso en curso Servidor principal de practica Complemento de trabajo rapido

Preparando la primera VM:

Del concepto al arranque

Pasos para crear una VM (concepto)

Antes de entrar al laboratorio, el flujo conceptual:

  1. Descargar la imagen ISO del sistema operativo (Debian o Ubuntu Server).
  2. Crear la VM en VirtualBox: nombre, tipo de SO, RAM y cores.
  3. Crear el disco virtual: formato .vdi, tipo dinamico, tamano 20+ GB.
  4. Montar la ISO en la unidad optica virtual de la VM.
  5. Arrancar la VM - el sistema inicia desde la ISO y corre el instalador.
  6. Seguir el instalador: idioma, particionado, usuario, contrasena.
  7. Una vez instalado, desmontar la ISO y reiniciar la VM.

Particionado basico del disco

Al instalar Linux, el instalador nos pide como dividir el disco virtual. Esquema minimo:

Particion Sistema de archivos Tamano Funcion
/boot ext4 512 MB - 1 GB Archivos de arranque del kernel
/ (root) ext4 15-20 GB Sistema operativo completo
swap swap 1-2 GB Memoria virtual de intercambio

Usaremos el particionado guiado automatico del instalador de Debian/Ubuntu.
